REVIEW AREAS

1. Coordinate and state authority

- Camera state is local presentation state only.
- No camera action mutates ECEF position/velocity, UTC, latitude, longitude,
  transported frame or world-time rate.
- No planar travel accumulator or renderer-recentering model was reintroduced.
- The renderer remains raft-centred.

2. Camera ownership and lifecycle

- One unambiguous active camera/controller owns input.
- Mode changes do not leave stale listeners, animation callbacks or duplicate
  controls.
- Cinematic and embodied state restoration is deterministic.
- Resize and disposal paths are complete.

3. Scale, framing and numerical behaviour

- Scale curves are bounded, continuous, finite and monotonic where specified.
- Distance, altitude, optical pitch and framing target are intentionally
  separated.
- Near/far planes and matrices remain finite at all supported scales.
- Damping and transitions use presentation delta, not accelerated world time.
- Edge cases near vertical embodied look avoid singularities and yaw inversion.

4. Input and responsive behaviour

- Pointer, wheel, touch and pinch ownership is explicit.
- Browser scrolling/zoom prevention is scoped to the canvas.
- Transition-time input has a single documented policy.
- Controls remain usable after mode switches and resize/orientation changes.

5. Existing-system preservation

- `WaveField`, deterministic sea states, persistent foam and CPU/GPU sampling
  are not replaced or silently retuned.
- `RaftBuoyancy` and fixed-step physics are unchanged except for narrowly
  justified compatibility work.
- `?debug=buoyancy` and `?debug=ocean` remain functional.
- The visible tools launcher opens World/General, Buoyancy, Ocean and Camera;
  query flags are deep links, not separate implementations.
- `Hide all` does not mutate canonical or simulation state.

6. Audio

- The baseline non-positional Web Audio `Ambience` path remains valid.
- No Three.js `AudioListener` was invented solely for camera switching.
- If a listener legitimately exists, there is exactly one and it follows the
  active camera.

7. Ocean topology and performance

- Far-camera support has no visible finite edge by design.
- LOD/filtering changes affect presentation, not raft-sampled displacement.
- No unbounded per-frame allocations or unnecessary full-resolution work.
- 4K/mobile/far-view claims are backed by measurements.

8. Tests and documentation

- Existing tracked planetary, raft-water, sea-state and parity tests remain.
- New tests cover scale curves, modes, transitions, vertical look, isolation,
  input and serialisation boundaries.
- Documentation matches implementation and measured limits.
